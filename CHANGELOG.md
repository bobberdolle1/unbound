# Changelog - UNBOUND

Все значимые изменения проекта документируются в этом файле.


## [0.6.8] - 2026-09-11
### macOS SOCKS lifecycle and reproducible packaging

#### Fixed

- macOS `tpws` теперь обслуживает только SOCKS5: профили Ultimate и YouTube блокируют только исходящий UDP/443, а Discord TCP Bypass не изменяет UDP-трафик.
- Остановка UNBOUND завершает только процесс `tpws`, которым владеет текущий экземпляр; глобальные `killall tpws` удалены.
- Системный SOCKS настраивается только для сервиса, обслуживающего default route, и полностью очищается при остановке.
- Релизная упаковка macOS собирает ZIP, DMG и PKG вне File Provider, очищает `FinderInfo`/`ResourceFork`, переподписывает bundle и smoke-тестирует артефакты.

## [0.6.7] - 2026-09-08
### 🚀 Релиз UNBOUND v0.6.7 — Launchers Packaging & Acceptance Truth

#### Fixed
- **Windows hotfix: конкурентный старт движка и лавина Hostlist Sync**:
  - Повторный `Start()` одного уже запущенного профиля теперь идемпотентен: возвращает `nil`, а не ложную ошибку `another start already completed while this one was in progress`.
  - `StartEngine` синхронизирует UI с реально работающим движком без красного тоста, если конкурентный старт уже успешно завершился.
  - `SyncHostlists()` схлопывает конкурентные HTTP-запросы и использует 30-секундное окно свежести, устраняя 10–15 одинаковых `[HOSTLIST]` строк в секунду.

- **Восстановление .CMD / BAT Launchers в релизных сборках Windows**:
  - Устранена регрессия упаковки (packaging regression), из-за которой в архивы Windows перестали включаться готовые командные файлы быстрого запуска из `scripts/control_windows/`.
  - В релизный ZIP-архив Windows возвращены 6 штатных лаунчеров:
    - `general_recommended.cmd` — запуск рекомендованного профиля (`--cli --profile rec`);
    - `general_autotune.cmd` — запуск автоматического подбора AutoTune (`--cli --autotune`);
    - `general_universal.cmd` — запуск универсального профиля (`--cli --profile universal`);
    - `general_alt1_multisplit.cmd` — запуск профиля Alternative 1 (`--cli --profile alt1`);
    - `general_alt2_fake_tls.cmd` — запуск профиля Alternative 2 (`--cli --profile alt2`);
    - `service_control.cmd` — открытие интерактивного Control Center (`--control`).
  - Добавлен автоматический регрессионный тест `TestWindowsPackagingLaunchers`, проверяющий наличие всех 6 файлов, валидность аргументов, прав администратора и соответствие профилей текущему каталогу `Zapret 2 (winws)`.
- **Исправление приёмки WinDivert (Acceptance Probe Desync Truth)**:
  - В `runAcceptanceTest()` кандидат обновлён на канонический `MultiSplit (midsld)` (`--payload=tls_client_hello --lua-desync=multisplit:pos=midsld`).
  - В отличие от прямого `hostfakesplit:repeats=2` без middlebox-поглощения (где фейковые SNI вызывали TCP RST со стороны незаблокированного `1.1.1.1`), `multisplit` выполняет чистое сегментирование ClientHello через WinDivert и Lua-движок, позволяя удалённому серверу Cloudflare успешно завершить подлинное рукопожатие TLS 1.3 за ~400 мс.
- **Потоковое отображение и диагностика приёмки (Acceptance UX)**:
  - Скрипт `verify_uac_acceptance.ps1` переведён на потоковое чтение `StandardOutput` через `.NET` `ProcessStartInfo`, устраняя пустое окно консоли при запуске GUI-подсистемы `Unbound.exe`.
  - В `runAcceptanceTest()` добавлен вывод подробного блока `ACCEPTANCE FAILED: Stage: ... Root cause: ...` с принудительным `os.Stdout.Sync()` и `os.Stderr.Sync()` перед выходом.

## [0.6.6] - 2026-09-08
### 🛡️ Релиз UNBOUND v0.6.6 — Lifecycle & Kernel Acceptance Truth

#### Fixed

- **Фактический конечный автомат жизненного цикла CandidateProcess**:
  - Устранён критический дефект, при котором `Stop()` безусловно выставлял `stopped = true` до завершения процесса и возвращал `nil` даже при таймауте, создавая ложное доказательство завершения.
  - Внедрён строгий стейт-машин с состояниями `STARTING`, `CAPTURE_READY`, `STOPPING`, `EXITED`, `STOP_FAILED`.
  - Метод `Alive()` теперь отражает исключительно фактическое завершение системного процесса через `done chan struct{}` (ожидание дескриптора OS), а не намерение пользователя.
  - Ошибки вызова `taskkill.exe /F /T /PID` на Windows больше не поглощаются и корректно распространяются. Добавлено принудительное завершение через fallback kill при задержке остановки.
- **Защита от наложения процессов кандидатов (Process Overlap Invariant)**:
  - Аудит Strategy Lab: ликвидированы все случаи игнорирования ошибок остановки (`_ = proc.Stop()`).
  - При сбое завершения кандидата N цикл немедленно прерывается (`CLEANUP_FAILED`), и кандидат N+1 **никогда не запускается**. Гарантирован инвариант: максимум 1 одновременно живой процесс кандидата.
- **Истинное измерение Baseline без влияния фонового обхода**:
  - Перед измерением базовой доступности (baseline) запущенный ранее рабочий профиль останавливается, и система ожидает фактического перехода провайдера в статус `StatusStopped`.
  - Сбой остановки предыдущего профиля немедленно прерывает Strategy Lab с ошибкой, предотвращая ложные baseline-замеры через работающий обход.
- **Верификация остановки процесса-победителя (Winner Cleanup)**:
  - После проведения валидации сервиса остановка процесса-победителя `winnerProc.Stop()` строго верифицируется.
  - В случае сбоя освобождения дескрипторов сессия помечается как `ValidationStatusFailed` с ошибкой очистки, исключая появление процессов-сирот.
- **Транзакционный статус восстановления профиля (`RestorationStatus`)**:
  - В отчёт `StrategyLabReport` добавлено типизированное поле `RestorationStatus` (`RESTORED`, `NOT_NEEDED`, `FAILED`) и `RestorationError`.
  - Если до запуска Strategy Lab работал профиль и при завершении его не удалось восстановить, ошибка явно передаётся на фронтенд и отображается пользователю в виде предупреждающего баннера.
- **Протокольная изоляция и раздельные Baseline в режиме ANY**:
  - Устранён дефект, при котором в режиме `ANY` все кандидаты тестировались через общий диспетчер (TLS 1.3 первым), из-за чего QUIC-кандидаты ошибочно получали `PASS` от успешного TLS-соединения.
  - В режиме `ANY` вычисляется структурированная карта базовых замеров `BaselineMap` для HTTP, TLS 1.2, TLS 1.3 и QUIC.
  - Каждый кандидат тестируется **строго по своему фактическому протоколу** (`cand.TestedProtocol`).
  - Если протокол кандидата уже доступен напрямую без обхода, кандидат помечается статусом `NO_BYPASS_NEEDED` и не засчитывается в победители обхода.
  - Победитель и сохраняемый профиль сохраняют точный протестированный протокол (никогда не сохраняя абстрактный `ANY`).
- **Локаленезависимый и точечный парсер TCP Timestamps на Windows**:
  - Устранена уязвимость, при которой `netsh` проверял общее слово `"enabled"` и давал ложный PASS при выключенных RFC 1323 метках из-за сторонних параметров (Receive-Side Scaling, Fast Open).
  - Функция `parseNetshTimestamps` сканирует исключительно строку с кодом стандарта `1323`, анализирует локализованные значения (`allowed`, `disabled`, `разрешены`, `отключено`, `activé`, `zulässig`) и использует fallback на PowerShell `Get-NetTCPSetting`.
- **Реальное чтение состояния TCP Timestamps на Linux**:
  - Метод `checkTCPTimestampsBool()` под Linux переведён с заглушки `true` на реальное чтение системного состояния из `/proc/sys/net/ipv4/tcp_timestamps` и `sysctl -n net.ipv4.tcp_timestamps`.
- **Реальная валидация поддержки IPv6**:
  - Функция `CheckCandidateCapabilities` теперь проверяет наличие активных глобальных одноадресных IPv6-адресов на сетевых интерфейсах. При их отсутствии кандидаты с требованием `IPv6 = true` пропускаются со статусом `SKIPPED_UNSUPPORTED`.
- **Авторитетный реестр Lua-функций и автоматический вывод требований**:
  - `knownLuaFunctions` расширен всеми десинхронизирующими функциями из официального скрипта `zapret-antidpi.lua`.
  - Добавлена функция `deriveRequiredLuaFunctions`, автоматически извлекающая функции из аргументов `--lua-desync=` кандидата.
- **Строгая ядерная приёмка WinDivert (`--acceptance-test`)**:
  - Реализована проверка реального TLS 1.3 рукопожатия с отправкой ClientHello (`ProbeTLSVersion`), привязанного к строгому WinDivert-фильтру (`1.1.1.1:443` в обоих направлениях).
  - Любой сбой сетевого зонда, гибель процесса во время зонда или нечистая остановка приводят к немедленному ненулевому коду возврата CLI (1-5).
  - Статус `ALL CHECKS PASSED: KERNEL_RUNTIME_VERIFIED` выводится только при 100% успехе всех пошаговых проверок.
- **Скрипт приёмки `verify_uac_acceptance.ps1`**:
  - Актуализирован для версии v0.6.6 со строгой передачей кода возврата исполняемого файла.

## [0.6.5] - 2026-09-08
### 🎯 Релиз UNBOUND v0.6.5 — Acceptance & Result Integrity

#### Fixed

- **Исправление ранжирования кандидатов и изоляция WorkingCandidates**:
  - Устранён критический дефект v0.6.4, при котором неуспешные попытки (`START_FAILED`, `SKIPPED_UNSUPPORTED`, `CAPTURE_NOT_READY`) ошибочно добавлялись в `WorkingCandidates`, из-за чего при отсутствии работающих стратегий первый упавший кандидат выбирался как `BestCandidate`.
  - В отчёт `StrategyLabReport` введён раздельный срез `CandidateResults` для всех протестированных/пропущенных попыток. Массив `WorkingCandidates` строго ограничен кандидатами со статусом `PASS` (`passCount >= 2`).
  - `BestCandidate` выбирается исключительно при `len(WorkingCandidates) > 0`. Если работающие кандидаты не найдены, `BestCandidate = nil`, валидация сервиса пропускается и сохранение профиля блокируется.
- **Полноценная проверка системных требований кандидатов (Capability Check)**:
  - Реализована подлинная проверка стека TCP: требование `TimestampsRequired` теперь валидирует реальное состояние через `checkTCPTimestampsBool()` (netsh/sysctl), а не просто проверку имени ОС.
  - Подключены проверки `InboundTCP`, `InboundUDP`, `QUIC`, `IPv6`, `EngineMinVersion`, `RequiredLuaFunctions`, `FakePayloads` и `LuaModules`. Кандидаты, чьи требования не удовлетворены окружением, корректно пропускаются со статусом `SKIPPED_UNSUPPORTED`.
- **Сохранение ошибки `WaitErr` и устранение Data Race в CandidateProcess**:
  - В `OSZapretCandidateProcess` буферы `bytes.Buffer` заменены на потокобезопасный `safeBuffer` с мьютексом, ликвидируя гонку данных памяти между записью `exec.Cmd` и опросом готовности в `StrategyLabRunner`.
  - Жизненный цикл переведён на неразрушающий канал `done chan struct{}` с сохранением ошибки завершения `waitErr`. Вызовы `Alive()` больше не поглощают ошибку завершения, и `WaitErr()` гарантированно возвращает оригинальный `ExitError`.
- **Строгий маркер `CAPTURE_READY` из upstream zapret2**:
  - Готовность перехвата WinDivert теперь подтверждается исключительно точным совпадением канонической строки `windivert initialized. capture is started.` (`nfq2/nfqws.c:912`), исключая ложные срабатывания по частичным подстрокам.
- **Fail-Closed при генерации фильтра валидации**:
  - Если для разрешённых адресов валидации сервиса не удалось сгенерировать WinDivert-фильтр, валидация немедленно переходит в статус `FAILED`, предотвращая запуск победителя со старым или неполным фильтром.
- **Строгая семантика прикладного статуса HTTP/3**:
  - В `ProbeHTTP3` при проверке эндпоинта `youtube.com/generate_204` коды 4xx/5xx теперь переводят зонд в статус `StatusFail` (`FailHTTPStatus`), исключая ложное подтверждение прикладного уровня.
- **Сохранение фактического протокола (TestedProtocol) в DiscoveredProfile**:
  - При сохранении профиля, найденного в Strategy Lab (например, для TLS 1.2), модель `DiscoveredProfile` и системные аргументы фиксируют фактически протестированный протокол (`TestedProtocol`), а не метаданные кандидата из каталога.
- **Гарантированная эксклюзивность мутаций AutoHostlist**:
  - В `executeWithAutoHostlistPause` добавлена строгая проверка ошибки `Stop()`: при сбое остановки мутация немедленно отменяется. Подтверждается переход движка в статус `StatusStopped`.
  - Добавлена проверка возобновления работы профиля: ошибка перезапуска возвращается пользователю.
- **Проверка завершения процесса в Zapret2WindowsProvider**:
  - В `stopLocked` после вызова `taskkill` добавлен ограниченный опрос таблицы процессов через `tasklist`: статус `StatusStopped` выставляется только после реального исчезновения PID из системы.
- **Автономный режим приёмки драйвера (`--acceptance-test`) и релизный скрипт**:
  - В CLI добавлен автономный флаг `Unbound.exe --acceptance-test`, выполняющий строго изолированный (1.1.1.1:443) тестовый запуск `winws2.exe` с WinDivert, ожидание точного маркера `CAPTURE_READY`, сетевой замер, проверку живости и подтверждение освобождения дескрипторов.
  - Скрипт `scripts/windows/verify_uac_acceptance.ps1` переписан на вызов `--acceptance-test` и включён напрямую в релизный ZIP-архив Windows для проведения приёмки на пользовательской машине без установленного компилятора Go.

## [0.6.4] - 2026-09-08
### 🎯 Релиз UNBOUND v0.6.4 — Strategy Lab End-to-End Truth

#### Fixed

- **Протокольно-ориентированное базовое измерение (Baseline)**:
  - Устранён критический дефект, когда `RunStrategyLab` всегда измерял baseline через TCP HTTP на 80 порту независимо от `cfg.Protocol`, что приводило к ложным ранним выходам (например, при заблокированном QUIC или TLS 1.2, но доступном HTTP).
  - Внедрены канонические методы `ProbeStrategyLabBaseline` и `ProbeTargetProtocol`: baseline для QUIC измеряется через QUIC, для TLS 1.2 — через TLS 1.2, для TLS 1.3 — через TLS 1.3, для HTTP — через HTTP.
  - В интерфейсе и отчётах отображается точный статус протокола (`Baseline QUIC`, `Baseline TLS 1.3`, `Baseline HTTP` и т.д.).
- **Реальная валидация произвольных целей (Custom Target)**:
  - Ликвидирована фиктивная валидация произвольных целей (`Custom => true` без запуска процесса).
  - Для победителя в любом профиле (включая Custom) генерируется строгий WinDivert-фильтр, запускается изолированный процесс, подтверждается состояние `CAPTURE_READY`, сбрасывается пул соединений и проводится реальная проверка протокола при живом дочернем процессе.
- **Типизированный статус валидации сервисов (`ServiceValidationResult`)**:
  - Устранена бинарная `bool`-семантика валидации сервисов. Введён типизированный результат `ValidationStatus`: `VERIFIED`, `PARTIAL`, `NOT_VERIFIED`, `FAILED`.
  - Честная обработка несовместимых сервисов: для сервисов без поддержки QUIC на прикладном уровне (Discord / Steam) статус выставляется как `PARTIAL` с понятным объяснением, а не ошибочный `FAILED`.
  - YouTube QUIC: помимо транспортного рукопожатия QUIC v1, выполняется подлинный прикладной запрос HTTP/3 через `quic-go/http3`.
- **Строгая верификация Discord Gateway (RFC 6455 & Opcode 10)**:
  - В `ProbeDiscordGatewayWithTarget` добавлена строгая проверка заголовка `Sec-WebSocket-Accept` по алгоритму RFC 6455 (`base64(SHA1(Sec-WebSocket-Key + GUID))`).
  - Полноценный парсер фреймов WebSocket: декодирование длины полезной нагрузки (7-bit, 126 16-bit, 127 64-bit), отсечение маскированных фреймов от сервера и управляющих фреймов.
  - Строгий JSON-парсинг Discord Opcode 10 Hello (`op == 10`, `heartbeat_interval > 0`) без использования хрупкого строкового поиска.
- **Требование активного состояния `CAPTURE_READY` и контроль жизненного цикла**:
  - `StartCandidate` больше не возвращает процесс в состоянии `ProcessStateRunning` без подтверждения старта перехвата: требуется стабильный маркер upstream zapret2 (`windivert initialized. capture is started.`).
  - Режим `dry-run` отделён от реального перехвата статусом `ProcessStateDryRunValidated`.
  - В интерфейс `CandidateProcess` добавлены методы `Alive()` и `WaitErr()`. Проверка живости процесса выполняется до и после каждой попытки зондирования, выявляя краш движка (`ENGINE_EXITED`) вместо ошибочного статуса сетевого сбоя.
- **Ликвидация окна TOCTOU в AutoHostlist через атомарный `O_APPEND` и эксклюзивную транзакцию**:
  - Метод `AddDomain` переведён на прямой атомарный `os.O_APPEND`, исключающий перезапись файла и конкурентные потери данных с `winws2`.
  - Для мутаций удаления (`RemoveDomain`, `ClearDynamicList`, `PromoteDomain`) внедрена эксклюзивная транзакция в `app.go`: активный профиль AutoHostlist временно приостанавливается, диск синхронизируется, изменения записываются атомарно, и профиль возобновляет работу.
  - В `ClearDynamicList` добавлена обязательная предварительная синхронизация с диском перед выставлением tombstones: удаляются как домены из памяти, так и домены, дописанные `winws2` на диск.
- **Безопасное сохранение стратегий в интерфейсе (Safe Save Policy)**:
  - При статусе `FAILED` кнопка сохранения блокируется с выводом ошибки валидации.
  - При статусе `PARTIAL` или `NOT_VERIFIED` отображается предупреждающий баннер и чекбокс подтверждения для безопасного сохранения.
  - Отображаются значки статуса: `✓ Проверено (VERIFIED)`, `⚠ Частично проверено (PARTIAL)`, `○ Не проверено (NOT VERIFIED)`, `✕ Ошибка валидации (FAILED)`.
- **Проверка системных требований кандидатов и Fail-Closed для невалидных протоколов**:
  - Реализована функция `CheckCandidateCapabilities`, пропускающая неподдерживаемые кандидаты (`SKIPPED_UNSUPPORTED`) вместо регистрации сетевого сбоя.
  - При передаче неподдерживаемого протокола Strategy Lab не откатывается на весь каталог, а возвращает строгую ошибку.

## [0.6.3] - 2026-09-07
### 🎯 Релиз UNBOUND v0.6.3 — Protocol Truth & Adaptive Correctness

#### Fixed

- **Настоящая реализация QUIC v1 (RFC 9000 & RFC 9001) через `quic-go`**:
  - Устранена критическая проблема v0.6.2 с кустарной псевдо-сборкой QUIC-пакетов без обязательного шифрования AEAD_AES_128_GCM, деривации секретов HKDF, защиты заголовка и транспортных параметров QUIC.

Рантайм-часть двойной поддержки сделана правильно: `UnboundAppDelegate` смотрит на `systemVersion` и поднимает скевоморфный контроллер до iOS 7, современный — после. Не сходятся сборка и упаковка:

### Критические исправления UI и работа без GitHub Actions

#### Исправлено
- **Сворачивание в трей больше не выключает обход.** `HideWindowToTray()` вызывал `manager.Stop()`, поэтому кнопка «Закрыть в трей» и системный крестик окна (он идёт сюда же через `onBeforeClose`) молча останавливали обход DPI. Работа в фоне — единственная причина, по которой приложение живёт в трее, и пользователю ничего не сообщалось о том, что трафик перестал защищаться.
- **Кнопка «Завершить winws2.exe» теперь завершает winws2.exe.** `KillWinws2()` вызывал `KillConflicts()`, чей список процессов намеренно исключает `winws2.exe` («не наш winws2.exe»). То есть единственная кнопка, обязанная убить наш движок, была единственной, которая гарантированно этого не делала, — а UI при этом рапортовал «Все процессы winws2 завершены». Аварийное завершение теперь сначала штатно останавливает процесс (чтобы тот убрал за собой правила файрвола), затем добивает осиротевший `winws2.exe` и освобождает драйвер WinDivert. Ошибка больше не уходит молча в консоль.
- `esModuleInterop: false` во фронтенде — опция, которую TypeScript 7 отвергает как устаревшую.
- `build_all.sh` вычислял версию, но никуда её не прошивал: `--version 2.6.0` собирал бинарник, который всё равно сообщал версию, вкомпилированную в `engine.Version`.

#### Android: VPN больше не убивает интернет на устройстве
`UnboundVpnService` поднимал TUN-интерфейс и заворачивал в него весь трафик (`addRoute("0.0.0.0", 0)` и `addRoute("::", 0)`), при том что петля пересылки пакетов не реализована — её тело состоит из трёх TODO, она читает пакеты и выбрасывает их, — а `startLocalProxy()` целиком закомментирован, но пишет в лог «Local proxy started on 127.0.0.1:1080».

Это хуже, чем «обход не работает»: за TUN нет ничего, поэтому включение VPN **полностью лишало устройство интернета** во всех приложениях, пока его не выключат. `BootReceiver` и `WifiStateReceiver` при этом умеют включать VPN сами — при загрузке и при смене Wi-Fi, так что пользователь мог получить телефон без связи, не понимая причины.

- Добавлен флаг `PACKET_RELAY_IMPLEMENTED`; пока он `false`, `startVpn()` отказывается поднимать интерфейс и сообщает причину вместо того, чтобы обрубить связь.
- Убрана ложная строка лога про запущенный прокси — она уводила в сторону любого, кто читал logcat, разбираясь с мёртвым соединением.
- В README статус Android изменён на ❌ с объяснением, что именно не реализовано и какими двумя путями это доделывается.

#### Ревизия остальных платформ
- **OpenWRT** оказался самой добротной из непроверенных платформ: настоящий пакетный Makefile, собирающий `nfqws` из исходников, procd-init, UCI-конфиг и nftables-include.
- **iOS (theos)** — рабочий по устройству tweak: настраивает SOCKS/HTTP-прокси на `127.0.0.1:1993` и поднимает `unbound-tpws`.
- **tvOS** в текущем виде **не соберётся**: `UnboundTunnelEngine.c` вызывает `tpws_init()` и `tpws_run_loop()`, которых нет ни в одном файле репозитория.

#### Проверено на живом ядре
- Правила iptables, которые генерирует Linux-провайдер, до сих пор сверялись только как строки. Добавлены тесты, скармливающие сгенерированные спецификации настоящему `iptables`: каждый встроенный профиль применяется ядром и удаляется той же спецификацией, которой был добавлен (`Flush()` удаляет по точному совпадению, а не по индексу, поэтому расхождение оставило бы правила висеть). Тесты требуют root и явного `UNBOUND_FIREWALL_TEST=1`, ставят правила в цепочку, в которую никто не переходит, и убирают её за собой. Проверено, что они действительно ловят поломку: неверный `--connbytes-mode` и выход `--queue-num` за диапазон дают падение с точной диагностикой от ядра.
- Бэкенд nftables на живом ядре подтвердить не удалось: в тестовой среде нет модуля `nft_queue` (при том, что compat-таргет `xt_NFQUEUE` через iptables работает). Тест это распознаёт и скипается с явным сообщением, а не выдаёт ложное «прошло».

#### Удалён мёртвый код
- `providers.ValidateBinaries` — ни одного вызова, и на Windows требовал `nfqws.exe`, тогда как движок называется `winws2.exe`. Дублировал `StartupValidator.validateBinaries`, который реально используется.
- `engine.ValidateAdminPrivileges` — ни одного вызова, и на Windows вызывал заглушку `checkWindowsAdmin()`, всегда возвращавшую ошибку «admin check not implemented».

#### Работа без GitHub Actions
GitHub Actions на репозитории недоступен из-за ограничения биллинга на уровне аккаунта, поэтому автоматических проверок на пуш нет.

- `scripts/check.sh` повторяет `.github/workflows/ci.yml` шаг в шаг: `gofmt`, `go vet` под три ОС, `go test -race`, кросс-компиляция под шесть пар GOOS/GOARCH, сборка интерфейса и сайта. Возвращает ненулевой код при любой неудаче, поэтому вешается на `pre-push`.
- `Makefile` с задачами `check`, `quick`, `build`, `gui`, `site`, `deploy-site`, `install-hooks`.
- В README описано, как выпускать релиз и публиковать сайт вручную, пока Actions не заработает. Сами workflow'ы уже в репозитории и заработают без правок.

### Smart TV — Обход DPI на телевизорах (без роутера)
- **LG WebOS (rooted)**:
  - Кросс-компиляция `nfqws` из bol-van/zapret для WebOS ARM (`armv7a-neon-webos-linux-gnueabi`).
  - Enact/React фронтенд с полной навигацией через D-pad пульта (Spotlight).
  - Фоновый сервис через webosbrew (`/var/lib/webosbrew/init.d/`) — автозапуск при включении ТВ.
  - Прозрачный перехват трафика через iptables NFQUEUE — весь HTTPS-трафик YouTube проходит через nfqws.
  - Luna-сервис интеграция через `org.webosbrew.hbchannel.service` (root-выполнение команд).
  - Профили: Default / Aggressive / Lite с настраиваемыми аргументами zapret.
- **Apple tvOS (17+)**:
  - `NEPacketTunnelProvider` через официальный NetworkExtension — без джейлбрейка.
  - Адаптация C-движка `tpws` (из theos/unbound-legacy) для tvOS ARM64.
  - SwiftUI интерфейс с элегантным тогглом и фокус-навигацией Siri Remote.
  - Локальный SOCKS-прокси режим (песочница tvOS, без root).
  - Swift Package Manager конфигурация сборки.
- **Документация**: `docs/SMART_TV.md` — полная архитектура, инструкции сборки и деплоя.
