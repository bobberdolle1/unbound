# 🛡 Политика безопасности и Гарантии приватности UNBOUND

Этот документ описывает архитектуру безопасности, границы гарантий, выполненные исправления привилегий и способы самостоятельной проверки **UNBOUND**.

---

## 🔒 1. Гарантии и границы

Следующие утверждения относятся к коду и официальным архивам этого репозитория:

| Принцип | Состояние | Описание |
| :--- | :---: | :--- |
| **No telemetry** | ✅ | В коде нет метрик, аналитики и трекеров. Сетевые обращения выполняют только явные пользовательские функции: обновление, синхронизация списков, диагностика и AutoTune. |
| **No account/backend** | ✅ | Нет серверов авторизации, учёта пользователей или промежуточного трафик-прокси UNBOUND. |
| **No Root CA / MITM** | ✅ | Приложение не устанавливает корневые сертификаты и не расшифровывает HTTPS. |
| **Local traffic handling** | ✅ | Windows/Linux обрабатывают пакеты локально; macOS направляет выбранный TCP-трафик в локальный `tpws --socks` (`127.0.0.1:9888`). Трафик не уходит на узлы UNBOUND. |
| **No passwordless sudoers** | ✅ | UNBOUND не создаёт правил `NOPASSWD` в `/etc/sudoers.d/` на macOS или Linux; обновлённый macOS `.pkg` активно удаляет устаревший файл `/etc/sudoers.d/unbound_zapret`. |
| **No bundled adware** | ✅ | В официальной сборке нет рекламных SDK, майнеров или рекламной подмены `hosts`. |

## 🚨 2. Важное уведомление безопасности для пользователей macOS (Устранение уязвимости `sudoers`)

В устаревших сборочных скриптах macOS-установщика (`scripts/build/build_pkg.sh`) и орфанном коде раннего провайдера macOS присутствовала критическая ошибка конфигурации привилегий: создавался файл `/etc/sudoers.d/unbound_zapret` со строкой `ALL ALL=(ALL) NOPASSWD: /sbin/pfctl, ALL`, где завершающий токен `, ALL` в грамматике `sudoers` предоставлял локальным процессам беспарольное повышение привилегий (`sudo`) для любых команд.

### Что исправлено:
1. **Полное удаление создания `sudoers`-правил**: ни `.pkg`-установщик (`scripts/build/build_pkg.sh`), ни runtime-провайдер macOS (`engine/providers/zapret_macos.go`) больше никогда не создают файлов в `/etc/sudoers.d/`.
2. **Активная автоматическая ремедиация при обновлении**: скрипт `postinstall` актуального macOS `.pkg`-установщика принудительно выполняет `rm -f /etc/sudoers.d/unbound_zapret`, а формула Homebrew Cask (`Casks/unbound.rb`) удаляет этот путь при деинсталляции.
3. **Строгая область снятия карантина Gatekeeper**: вспомогательные скрипты `scripts/control_macOS/*.command` снимают `com.apple.quarantine` исключительно с `Unbound.app` и не перезаписывают hardened runtime entitlements пакета.

### Ручная проверка и очистка (macOS):
Если вы ранее устанавливали старую сборку UNBOUND через `.pkg` на macOS, проверьте отсутствие устаревшего файла и при необходимости удалите его вручную:

```bash
sudo rm -f /etc/sudoers.d/unbound_zapret
```

## 🔬 3. Разбор технологии: Как UNBOUND обходит DPI без рисков для безопасности

UNBOUND не устанавливает корневой сертификат и не расшифровывает содержимое TLS:

```
Windows: приложение → WinDivert/winws2 → целевой сервер
Linux:   приложение → NFQUEUE/nfqws2 → целевой сервер
macOS:   приложение → system SOCKS → локальный tpws --socks (127.0.0.1:9888) → целевой сервер
```

- TLS остаётся сквозным между клиентом и целевым сервером.
- Windows и Linux применяют десинхронизацию к начальному TCP/UDP-трафику согласно профилю или проверенной области AutoTune vNext (`ServiceScope` / `ServiceGraph`).
- На повышенных правах в Windows runtime-бинарники распаковываются не в пользовательский `%TEMP%`, а в изолированный каталог `%ProgramData%\Unbound\runtime-<pid>-<rand>` со строгим DACL (`SYSTEM` + `Administrators`) и проверкой отсутствия symlink/reparse-point до запуска `winws2.exe`.
- На macOS `tpws --socks` обрабатывает TCP-поток локально через системный SOCKS5-прокси активного маршрута по умолчанию и восстанавливает исходные сетевые настройки при остановке.
- Локальная история результатов AutoTune vNext (`autotune_vnext_outcomes.json`) использует анонимизированные HMAC-SHA256 ключи контекста (`autotune_vnext_context.key` с правами доступа только владельца) и не сохраняет сырые сетевые адреса или пользовательские идентификаторы.

## ⚠️ 4. Предупреждения антивирусов (WinDivert & False Positives)

На платформе Windows ядро обхода использует драйвер перехвата пакетов **WinDivert** (`WinDivert64.sys` / `WinDivert.dll`).

### Почему антивирусы могут реагировать?
1. **Категория RiskTool / PUA (Potentially Unwanted Application)**:
   - WinDivert — легальный инструмент с цифровой подписью для низкоуровневой работы с сетевым стеком Windows.
   - Некоторые антивирусы (Kaspersky, Microsoft Defender, Avast) по умолчанию помечают любые утилиты захвата пакетов как `RiskTool.Multi.WinDivert` или `PUA`.
2. **WinDivert является компонентом с открытым исходным кодом**:
   - Используемый файл драйвера закреплён SHA256-манифестом UNBOUND и проверяется до запуска.

> 💡 **Рекомендация**: при предупреждении антивируса сначала сверьте `SHA256SUMS.txt` релиза и `BUNDLE_SHA256SUMS.txt` внутри архива. Добавляйте исключение только для проверенной распакованной папки и только осознанно.

## 🗝 5. Криптографический контроль целостности бинарников (Asset Provenance)

Встроенные исполняемые файлы, драйверы, Lua-скрипты и сигнатуры зафиксированы в **`engine/ENGINE_ASSETS.sha256`** и проверяются до привилегированного запуска.

Происхождение актуальных Zapret-компонентов — upstream tag, commit, URL, SHA256 исходного архива, лицензия и список путей — записано в **`engine/ENGINE_PROVENANCE.json`**.

Локальная проверка исходного дерева:

```bash
./scripts/engine-assets.sh verify
```

В GUI раздел **Настройки → Безопасность и Провенанс** сверяет встроенные ассеты. В релизе `BUNDLE_SHA256SUMS.txt` покрывает содержимое архива, а опубликованный `SHA256SUMS.txt` — сами архивы.

## 🛠 6. Как самостоятельно убедиться в безопасности UNBOUND

1. **Сборка из исходников**:
   Вы можете полностью собрать бинарники самостоятельно с помощью Go, Wails и Node.js:
   ```bash
   git clone https://github.com/bobberdolle1/unbound.git
   cd unbound
   make check
   make build
   ```
2. **Анализ сетевого трафика (Wireshark / tcpdump)**:
   Сопоставьте исходящие соединения с выбранной функцией (целевой сайт, AutoTune/диагностика, обновление или источник списка) и убедитесь, что TLS-сертификат сайта выпущен его реальным центром сертификации, а не локальным CA.
