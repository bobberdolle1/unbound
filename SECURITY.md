# 🛡 Политика безопасности и Гарантии приватности UNBOUND

Этот документ описывает архитектуру безопасности, границы гарантий и способы самостоятельной проверки **UNBOUND Refresh**.

---

## 🔒 1. Гарантии и границы

Следующие утверждения относятся к коду и официальным архивам этого репозитория:

| Принцип | Состояние | Описание |
| :--- | :---: | :--- |
| **No telemetry** | ✅ | В коде нет метрик, аналитики и трекеров. Сетевые обращения выполняют пользовательские функции: обновление, синхронизация списков, диагностика и AutoTune. |
| **No account/backend** | ✅ | Нет серверов авторизации, учёта пользователей или промежуточного трафик-прокси UNBOUND. |
| **No Root CA / MITM** | ✅ | Приложение не устанавливает корневые сертификаты и не расшифровывает HTTPS. |
| **Local traffic handling** | ✅ | Windows/Linux меняют пакеты локально; macOS перенаправляет выбранный TCP-трафик в локальный `tpws`. Трафик не уходит на узлы UNBOUND. |
| **No bundled adware** | ✅ | В официальной сборке нет рекламных SDK, майнеров или рекламной подмены `hosts`. |

## 🔬 2. Разбор технологии: Как UNBOUND обходит DPI без рисков для безопасности

UNBOUND не устанавливает корневой сертификат и не расшифровывает содержимое TLS:

```
Windows: приложение → WinDivert/winws2 → целевой сервер
Linux:   приложение → NFQUEUE/nfqws2 → целевой сервер
macOS:   приложение → pf → локальный tpws → целевой сервер
```

- TLS остаётся сквозным между клиентом и целевым сервером.
- Windows/Linux применяют десинхронизацию к начальному TCP/UDP-трафику согласно профилю.
- macOS `tpws` меняет TCP-поток локально; UDP/QUIC он не обрабатывает.

## ⚠️ 3. Предупреждения антивирусов (WinDivert & False Positives)

На платформе Windows ядро обхода использует драйвер перехвата пакетов **WinDivert** (`WinDivert64.sys` / `WinDivert.dll`).

### Почему антивирусы могут реагировать?
1. **Категория RiskTool / PUA (Potentially Unwanted Application)**:
   - WinDivert — это легальный инструмент с цифровой подписью для низкоуровневой работы с сетевым стеком Windows.
   - Некоторые антивирусы (Kaspersky, Windows Defender, Avast) по умолчанию помечают *любые* утилиты захвата пакетов как `RiskTool.Multi.WinDivert` или `PUA`.
2. **WinDivert является компонентом с открытым исходным кодом**:
   - WinDivert поддерживается как open-source проект; используемый файл драйвера отдельно закреплён SHA256-манифестом UNBOUND.

> 💡 **Рекомендация**: при предупреждении антивируса сначала сверьте `SHA256SUMS.txt` релиза и `BUNDLE_SHA256SUMS.txt` внутри архива. Добавляйте исключение только для проверенной распакованной папки и только осознанно.

## 🗝 4. Криптографический контроль целостности бинарников (Asset Provenance)

Встроенные исполняемые файлы, драйверы, Lua-скрипты и сигнатуры зафиксированы в **`engine/ENGINE_ASSETS.sha256`** и проверяются до привилегированного запуска.

Происхождение актуальных Zapret-компонентов — upstream tag, commit, URL, SHA256 исходного архива, лицензия и список путей — записано в **`engine/ENGINE_PROVENANCE.json`**.

Локальная проверка исходного дерева:

```bash
./scripts/engine-assets.sh verify
```

В GUI раздел **Настройки → Безопасность и Провенанс** сверяет встроенные ассеты. В релизе `BUNDLE_SHA256SUMS.txt` покрывает содержимое архива, а опубликованный `SHA256SUMS.txt` — сами архивы.

## 🛠 5. Как самостоятельно убедиться в безопасности UNBOUND

1. **Сборка из исходников**:
   Вы можете полностью собрать бинарники самостоятельно с помощью Go, Wails и Node.js:
   ```bash
   git clone https://github.com/bobberdolle1/unbound.git
   cd unbound
   make check
   make build
   ```
2. **Анализ сетевого трафика (Wireshark / tcpdump)**:
   Сопоставьте исходящие соединения с выбранной функцией (целевой сайт, AutoTune/диагностика, обновление или источник списка) и убедитесь, что TLS-сертификат сайта выпущен его реальным центром сертификации, а не локальным CA.
