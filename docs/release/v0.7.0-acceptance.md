# v0.7.0 release acceptance

## Platform packaging

Windows and macOS canonical build/package gates passed from the immutable v0.7.0 source. macOS ZIP identity, deep/strict codesign, DMG mount, and PKG expansion passed before publication.

## Windows bundled helper limitation

`run_offline_physical_acceptance.ps1` on `DESKTOP-MNEHCPT` hung before `PREPARED` while collecting `Get-NetIPConfiguration`, `Get-NetRoute`, and related NetTCPIP diagnostics. This is recorded as `ENVIRONMENT_SPECIFIC_NETTCPIP_PROVIDER_HANG`; it is not a v0.7.0 binary-identity failure. The data plane was cleaned and no `Unbound` or `winws2` process remained.

## Published Windows external acceptance

A fresh GitHub-downloaded Windows ZIP passed artifact identity and final process cleanup. Its external bounded coordinator recorded failures for clean-data-plane verification, kernel acceptance, representative profile lifecycle, doctor, AutoTune smoke, and launchers. The published asset is immutable and was not replaced.

The coordinator's first invocation had an argument-binding defect; its corrected invocation retained only terminal stage status and removed per-command redirected logs. The terminal evidence is insufficient to attribute those failures to a specific product component. This record therefore does not claim successful published Windows product acceptance.

## Tooling backlog

Target v0.7.1 tooling hardening: make Windows `Get-NetworkSnapshot` diagnostics individually time-bounded, terminate timed-out diagnostic child trees, and persist per-command external-acceptance stdout/stderr before cleanup.

Current bounded-host AutoTune effectiveness and the full multi-host service graph remain unestablished. Prior vNext evidence covers a bounded hostname scope, not full service-graph effectiveness.
