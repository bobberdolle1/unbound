# 🕵️ Технический отчёт по безопасности UNBOUND

Документ фиксирует внутреннюю проверку архитектуры, зависимостей и сетевого поведения **UNBOUND Refresh (`v0.2.1`)**. Это не внешний аудит и не сертификация.

---

## 1. Сравнительный анализ архитектуры безопасности

| Критерий безопасности | UNBOUND Refresh | Вредоносные / Непроверенные форки |
| :--- | :--- | :--- |
| **Принцип работы** | Локальная обработка через WinDivert/NFQUEUE либо локальный `tpws` на macOS | Перенаправление на неизвестный внешний HTTP/SOCKS/VPN-узел |
| **Управление SSL/TLS** | Прямой TLS-handshake с целевым сервером | MITM-перехват с корневым CA |
| **Конфиденциальность данных** | TLS-содержимое не расшифровывается | Трафик расшифровывается на MITM-прокси |
| **Сетевые правила** | Временные правила `nftables` / `pf` anchor / WinDivert | Необъяснённая постоянная модификация DNS или `hosts` |
| **Исходный код** | Код UNBOUND открыт; вендоренные бинарники закреплены SHA256 и provenance | Закрытые инъекции или неподтверждённые бинарники |
| **Телеметрия** | Аналитики нет; функции обновления, списков, диагностики и AutoTune делают документированные сетевые запросы | Скрытый сбор IP, истории и идентификаторов |

---

## 2. Анализ зависимостей и бинарных компонентов

1. **Go-модули (`go.mod`)**:
   - Основные прямые зависимости: Wails, `systray` и `golang.org/x/sys`; полный граф закреплён в `go.mod`/`go.sum`.
2. **Фронтенд-зависимости (`frontend/package.json`)**:
   - React, Tailwind CSS, Vite, TypeScript и тестовые библиотеки; lockfile закрепляет разрешённые версии.
   - В прямых зависимостях нет аналитических SDK (Google Analytics, Mixpanel, Sentry, PostHog, Segment).
3. **Шрифты и графические ресурсы**:
   - Шрифты Inter, Comic Neue, Permanent Marker и VT323 находятся в `frontend/src/fonts/`.
   - Во время работы шрифты не загружаются с Google Fonts или CDN.

## 3. Манифест целостности ассетов (`ENGINE_ASSETS.sha256`)

Все поставляемые бинарные модули (`winws2.exe`, `WinDivert.dll`, `WinDivert64.sys`, `tpws`, Lua-скрипты и фальшивые сигнатуры `zero_1024.bin`, `tls_clienthello_*.bin`) покрыты криптографическими контрольными суммами SHA256.

`scripts/engine-assets.sh verify` проверяет содержимое и полный перечень файлов в контролируемых каталогах: изменение либо добавление файла завершает проверку ошибкой. Runtime-проверка сверяет каждый встроенный файл перед запуском движка.

## 4. Пошаговое руководство по самостоятельной верификации

Проверить заявленные свойства UNBOUND можно следующими способами:

### Способ А. Проверка сетевого трафика через Wireshark
1. Откройте **Wireshark** и начните захват пакетов на вашем сетевом интерфейсе.
2. Запустите UNBOUND и включите обход DPI.
3. Откройте YouTube или Discord.
4. Проверьте фильтр `ip.dst`: трафик идет **напрямую к IP-адресам Google / Discord**, минуя какие-либо сторонние промежуточные IP.
5. Проверьте TLS Сертификат сайта в браузере: вы увидите оригинальный сертификат Google Trust Services / DigiCert.

### Способ Б. Локальная сборка из исходников
```bash
git clone https://github.com/bobberdolle1/unbound.git
cd unbound
make check
make build
```

### Способ В. Проверка целостности ассетов
```bash
./scripts/check.sh assets
```
Проверяет все записи текущего манифеста (на момент `v0.2.1` — 136 файлов).
