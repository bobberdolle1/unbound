# 🕵️ Технический отчёт по безопасности UNBOUND

Документ фиксирует внутреннюю проверку архитектуры, зависимостей, модели привилегий и сетевого поведения **UNBOUND (`v0.8.x`)**. Это внутренний инженерный аудит, а не внешняя сертификация.

---

## 1. Сравнительный анализ архитектуры безопасности

| Критерий безопасности | UNBOUND | Вредоносные / Непроверенные форки |
| :--- | :--- | :--- |
| **Принцип работы** | Локальная обработка через WinDivert/NFQUEUE либо локальный `tpws --socks` на macOS | Перенаправление на неизвестный внешний HTTP/SOCKS/VPN-узел |
| **Управление SSL/TLS** | Прямой сквозной TLS-handshake с целевым сервером | MITM-перехват с установкой корневого CA |
| **Конфиденциальность данных** | TLS-содержимое не расшифровывается | Трафик расшифровывается на промежуточном прокси |
| **Сетевые правила** | Транзакционные правила `nftables` / WinDivert / default-route SOCKS с верификацией очистки | Необъяснённая постоянная модификация маршрутов, `sudoers` или `hosts` |
| **Исходный код и ассеты** | Код UNBOUND открыт (GPL-3.0); вендоренные бинарники закреплены SHA256 и provenance | Закрытые инъекции или неподтверждённые бинарники |
| **Телеметрия** | Аналитики нет; обновление, списки, диагностика и AutoTune делают документированные запросы | Скрытый сбор IP, истории и идентификаторов |

## 2. Анализ зависимостей и бинарных компонентов

1. **Go-модули (`go.mod`, Go 1.26+)**:
   - Основные прямые зависимости: Wails v2, `quic-go`, `systray`, `golang.org/x/net` и `golang.org/x/sys`; полный граф закреплён криптографическими суммами в `go.sum`.
2. **Фронтенд-зависимости (`frontend/package.json`)**:
   - React 18, Tailwind CSS v4, Vite, TypeScript и Vitest; `package-lock.json` закрепляет точные версии пакетов.
   - В зависимостях отсутствуют аналитические и телеметрические SDK (Google Analytics, Mixpanel, Sentry, PostHog, Segment).
3. **Шрифты и графические ресурсы**:
   - В `frontend/src/fonts/` поставляется исключительно локальный шрифт **Inter** (`.woff2` для подмножеств `latin`/`cyrillic`, лицензия OFL-1.1); устаревшие декоративные шрифты удалены из репозитория и `scripts/fetch-fonts.sh`.
   - Во время работы приложение не обращается к `fonts.googleapis.com` или внешним CDN.

## 3. Манифест целостности ассетов (`ENGINE_ASSETS.sha256`)

Все поставляемые бинарные модули (`winws2.exe`, `WinDivert.dll`, `WinDivert64.sys`, `nfqws2`, universal `tpws`, Lua-скрипты и сигнатуры `zero_*.bin`, `tls_clienthello_*.bin`, `quic_initial_*.bin`) покрыты криптографическими контрольными суммами SHA256.

`scripts/engine-assets.sh verify` проверяет как хеши, так и полный перечень файлов в контролируемых каталогах: любое изменение или появление лишнего файла завершает проверку ошибкой. В runtime `ExtractAssets()` сверяет каждый встроенный файл с `ENGINE_ASSETS.sha256` до привилегированного запуска движка.

## 4. Дополнение аудита `v0.8.x` (Ремедиация и усиление защиты)

По итогам комплексного аудита исходного дерева, скриптов сборки и платформенных провайдеров в ветке `v0.8.x` выполнены следующие меры безопасности:

1. **`[P0]` Ликвидация уязвимости `sudoers` на macOS и активная очистка**:
   - Из `scripts/build/build_pkg.sh` (`postinstall`) и `engine/providers/zapret_macos.go` полностью удалён устаревший механизм записи `/etc/sudoers.d/unbound_zapret` (`ALL ALL=(ALL) NOPASSWD: /sbin/pfctl, ALL`), допускавший беспарольное повышение привилегий локальных процессов.
   - В `postinstall` пакета `.pkg` добавлена активная ремедиация `rm -f /etc/sudoers.d/unbound_zapret` при обновлении/переустановке; удаление также закреплено в `Casks/unbound.rb`.
2. **Безопасная область `xattr` и сохранение Hardened Runtime на macOS**:
   - Из `scripts/control_macOS/*.command` удалены рекурсивные вызовы `xattr -cr "$DIR"` (опасные при запуске из `~/Downloads`) и переподписание без entitlements (`codesign --force --deep -s -`). Снятие `com.apple.quarantine` строго ограничено путём `Unbound.app`.
3. **Защищённая распаковка привилегированного runtime в Windows**:
   - При запуске с правами администратора `ExtractAssets()` размещает проверенные бинарники в `%ProgramData%\Unbound\runtime-<pid>-<rand>` с защищённым DACL (`PROTECTED_DACL_SECURITY_INFORMATION`, доступ только `SYSTEM` и `BUILTIN\Administrators`) и отклонением reparse points / симлинков, исключая подмену исполняемых файлов из пользовательского `%TEMP%`.
   - Исключения Microsoft Defender (`AddDefenderExclusion`) скорректированы на фактические директории `%ProgramData%\Unbound` и `%LOCALAPPDATA%\Unbound` с безопасным экранированием аргументов PowerShell.
4. **Приватность журнала истории AutoTune vNext (`engine/historyid` & `outcomeledger`)**:
   - Ключи контекста формируются локально через HMAC-SHA256 (`autotune_vnext_context.key` с правами владельца `0600` / ограниченным DACL); сырые IP-адреса, маршруты и сетевые идентификаторы не сохраняются на диск.
   - Bounded `TransferContract` выполняет чтение окна ответа строго в памяти без записи полезной нагрузки на диск.
5. **Бережное обращение с системным DNS**:
   - Сохранение настроек (`SaveSettings`) изменяет системный DNS только при явном переключении опции `SecureDNS`, игнорируя виртуальные/VPN/WSL-интерфейсы и не сбрасывая пользовательские корпоративные или локальные DNS-серверы.

## 5. Пошаговое руководство по самостоятельной верификации

### Способ А. Проверка сетевого трафика через Wireshark
1. Откройте **Wireshark** и начните захват пакетов на активном сетевом интерфейсе.
2. Запустите UNBOUND и включите профиль обхода или AutoTune vNext.
3. Откройте целевой ресурс (например, YouTube или Discord).
4. Проверьте фильтр `ip.dst`: трафик идёт **напрямую к IP-адресам целевого сервиса**, минуя сторонние промежуточные прокси.
5. Проверьте TLS-сертификат сайта в браузере: он подписан штатным публичным УЦ целевого сервиса.

### Способ Б. Локальная сборка и каноническая проверка из исходников
```bash
git clone https://github.com/bobberdolle1/unbound.git
cd unbound
make check
make build
```

### Способ В. Проверка целостности встроенных ассетов
```bash
./scripts/engine-assets.sh verify
```
